# Agent / AI System

Creatures, NPCs, enemies and turrets are a prefab plus a stack of `IBehaviourModule` components; one [AgentController.cs](Assets/Game/Scripts/agents/Controller/AgentController.cs) ticks them and arbitrates by priority — never a behaviour tree, never an `AgentController` subclass.

**Scope:** `Assets/Game/Scripts/agents/` (namespace `SpaceGame.Agents`, Assembly-CSharp, no asmdef). **Related:** [EntitySystem.md](EntitySystem.md) (older overview — profile/module tables there are stale, prefer this file), [MountSystem.md](MountSystem.md), [Persistence.md](Persistence.md), [WeaponSystem.md](WeaponSystem.md), [NavMeshSystem.md](NavMeshSystem.md), [SkyTribe.md](SkyTribe.md) (the Sky Tribe's faction/roster/city/flying-war-party model in full — this file only points at it), skill [.claude/skills/spacegame-agent/SKILL.md](.claude/skills/spacegame-agent/SKILL.md) + its `reference.md`.

## Model

- Three decisions, one owner each: **who to fight** = [AgentTargeting.cs](Assets/Game/Scripts/agents/AI/Targeting/AgentTargeting.cs); **where to go** = [AgentGoal.cs](Assets/Game/Scripts/agents/AI/Goals/AgentGoal.cs); **how to move** = [IMovementMotor.cs](Assets/Game/Scripts/agents/AI/Motors/IMovementMotor.cs). A module duplicating any of the three is the bug this design prevents.
- Modules return `MoveIntent?`. `null` = pass to the next module. `MoveIntent.Idle()` **claims the frame** and starves everything below — and a suppressing condition (`Frozen`, `Foamed`) starves the whole stack before it is reached: `AgentController.Awake` ensures a `StatusReceiver` on its own GameObject and `Update` idles the motor while `StatusReceiver.Suppressed` holds, side-effect modules included, so a frozen creature cannot bite either. The receiver is ensured here because a prefab without a `StatusReactionModule` had none at all — Clanker, ClankerOutrider, CrabWalker6, HumanoidRobot and RobotHorse simply ignored the cryo sprayer — and on its OWN object, never through `StatusReceiver.Ensure`, which resolves to the networked root and would give a mounted rider its mount's conditions. See [StatusEffects](Artifacts/StatusEffects.md).
- `ClaimsMovement == false` modules are side effects: ticked unconditionally, must return `null`.
- Facing is a **second channel**: `IFacingModule` overwrites the winning intent's face target after arbitration.
- `AgentTargeting` + `AgentGoal` are auto-added in `AgentController.Awake`. Modules are discovered via `GetComponentsInChildren<MonoBehaviour>(true)`; runtime additions need `RefreshModules()`.
- Riding (`MountModule` / `SteerModule` in [Modules/Riding/](Assets/Game/Scripts/agents/Modules/Riding/)) rides on this stack but is documented in [MountSystem.md](MountSystem.md). A mounted NPC is the *mount's* agent with the rider as cargo whose movement — and only movement — is switched off (`NpcPassenger`): `ClankerOutrider.prefab` is a robot horse on the Clankers' side carrying a Clanker, built by `RobotHorseBuilder` beside the wild, Fauna `RobotHorse.prefab` from one component list. **Neither horse can attack anything** — no `CloseCombatModule`, no kick, no trample, no weapon, on either side. A horse is transport: the outrider's `ChaseModule` carries its rider to `RobotHorseBuilder.ChaseStopDistance` (inside `ClankerBuilder.GunMinRange`…`GunMaxRange`) and stands, and the Clanker in the saddle does the shooting. **Gotcha:** never "fix" a passive mounted enemy by arming the animal — that makes "kill the rider" and "kill the horse" one move with two animations and hides which half is dangerous (`GDC-L1-SYS-0005`, `GDC-L1-SYS-0006`). The fix is that a seated rider keeps its side-effect modules; mechanism and the bug it replaced in [Vehicles.md](Vehicles.md). An animal is made rideable and packable by **fitting a saddle** ([Saddles.md](Saddles.md)); the agent-side piece is [`SaddleSocket`](Assets/Game/Scripts/agents/Modules/Riding/SaddleSocket.cs), which holds that state and enables the `MountModule` `AppaBuilder` adds **disabled**.

## Flows

**Per frame — `AgentController.Update`:**
1. `RefreshAuthority()` — if this machine does not own the agent: `TickPresentation(dt)` (`IPresentationModule` only) and **return**.
2. Bail if `Motor == null`. Build `AgentContext`.
3. Tick every side-effect module (`ClaimsMovement == false`) in discovery order, unconditionally.
4. Tick movement modules, priority DESC (ties by component order); **first non-null wins**. None → `MoveIntent.Idle()`.
5. `ApplyFacingOverride()` — `IFacingModule[]` by `FacingPriority` DESC, first `true` wins, overwrites `FacePosition`.
6. Speed-variation drift applied to `SpeedMultiplier` (`MoveToPosition` intents only; phase is saved).
7. `Motor.Tick(intent, dt)` → `animatorDriver.Tick(Motor.Velocity, Motor.IsImmobile, intent.IsRunning)`.

**Execution order:** −100 `NavMeshAgentMotor` · −50 `AgentTargeting` · −40 `ProvocationModule` · 0 `AgentController` · 50 `LeggedDriver` · 100 `LeggedLocomotion` (asmdef `SpaceGame.Locomotion`) · LateUpdate `AgentAnimatorDriver`, `EntityEquipmentController` aim.

**Attack:** authority module fires → damages/spawns locally → `AgentActionRelay.Broadcast(this, AgentAction.Melee|Ranged, origin, dir)` → peers `TryReadRay` and draw **presentation only** (no damage; `NetDamage` would bill the target once per machine).

**Caravan:** `NpcWorldSim` ticks `NpcGroup` records (lerp + `NpcTaskPlanner`) → player within `spawnRadius` → `NpcSpawn.Create` per `NpcGroupMemberSpec` in formation → members run their own AI → `despawnRadius` folds them back into the record. **War party:** goodwill reaches `AtWar` → `WarPartyDirector` opens a `War` and, once its cooldown clears, raises a `runtimeOnly` group at an unseen camp or a fallback point beyond staging distance, drawing its tier from the roster's `warPartyTiers` → the party follows a fuzzy trail fix refreshed after `trailInterval` without sight of its quarry — folded it catches up unseen to `staging + trailFuzz`; spawned, `NpcWorldSim.SteerSpawned` re-points the live leader (never a jump) → a quarry who leaves releases the party unresolved at once, and one never bound this session (a restored party) after `absentQuarryGrace` → Caught (this party's own `GroupMembership.GroupIdOf` dealt the blow: credited, which typically lifts the band out of `AtWar` and ends the whole war the same way decay or a crewmate's amends would — `WarNotice.GaveUp` fires from that band change, not from the resolve itself) / Defeated (`WarPartyRules.IsDefeated`; the sim marks `WipedOut` only when `IsWipedOut` holds — no `Live` member and no standing `NpcGroup.Fighters` entry, so a dismounted rider still fighting keeps the party in the field: credited, next party one tier stronger, war stays open, `WarNotice.Weakening`) / Abandoned (beyond `maxPursuitDistance`: no credit, no notice — only this party gives up; the war stays open and its cooldown restarts; never while `NpcWorldSim.IsInFlight` — `WarPartyRules.ShouldAbandon(..., inFlight)` — since a flying party sets out from its home site wherever that is; running the catch-up first was tried and still abandoned a Sky party raised 1.6 km from a moving quarry). **Flying war party (`sky-war-party`, wired by `RosterAuthoring.WireWorldSim`):** `ChooseOrigin` returns the `WorldSiteRegistry.TryFindByName(transport.homeSiteName)` site (any kind, airborne, observed or not), else the usual camp/fallback → folded and undelivered the record moves at `transport.travelSpeed` and catches up as any party → inside `spawnRadius`, `NpcWorldSim.Spawn` counts the planned members, spawns `transport.VesselFor(count)` (skiff if its `VesselSeats.Capacity` fits, else freighter: Sky tiers 0 and 1 skiff, tier 2 freighter) (riders counted with `NpcGroupComposition.Rides`, the one predicate for count and seating; riders beyond the vessel's seats go on foot with a warning) — boarding an empty hull of that prefab parked `Done` at its dock within `dockReuseRadius` if one is there, else `NpcSpawn.Create` at the record's position, `RiseToCruise` before the network spawn, prow toward `QuarryPoint` — spawns and stamps the members exactly as on foot, under the hull (Live and Fighters from the start), and `VesselPilot.Begin(dock, QuarryPoint, riders, despawnRadius)` seats them; `QuarryPoint` is the director's lead, else the goal, else the group's position, and the dock is the group's `NpcGroupTransport.DockPoint` slot around the home site (rings `dockSpacing` apart, lowest free slot, kept by a reused hull), so parked hulls never overlap → while aboard the group's position is the vessel's → `TickTransport` (polled every sim tick, before the `WipedOut` return) sets `Delivered` (`NpcGroupTransport.IsDelivered`) once nobody is seated, or the hull is wrecked or gone — a run that came home with riders aboard (no landing site) is NOT a delivery: in view it waits `transportRetryDelay` at its dock and is re-`Begin`-ed (`ShouldRelaunch`), out of view the group folds with it and flies in again; from then the group is an ordinary spawned party and the empty hull is despawned once every player is beyond `despawnRadius`. Fold while aboard: vessel despawned FIRST (its `OnNetworkDespawn` puts riders on the NavMesh), then members; the record keeps `Delivered` false and flies on from the vessel's position. A released or wiped-out party is not removed (`ReleaseGroup`, the `RemoveAll`) while its `Transport` is still out. Restore: undelivered spawns in a vessel again, delivered on foot. With no usable vessel prefab the sim logs an error and spawns the party on foot (`Delivered` true). Full walkthrough with numbers: [SkyTribe.md](SkyTribe.md) Flows.

## Multiplayer

- The **owner** machine runs the whole stack; every other machine runs only `IPresentationModule`s. Ownership, not server-ness — [AgentAuthority.cs](Assets/Game/Scripts/agents/Core/AgentAuthority.cs). Modules must contain **no** authority check; the controller already gated the tick.
- Body transform + animator replicate through `NetworkObject` / [NetAuthority.cs](Assets/Game/Scripts/Core/Multiplayer/Authority/NetAuthority.cs), which disables listed simulation drivers on remotes.
- Attacks replicate as `NetMsg.AgentActed` (69) via `AgentActionRelay`; damage stays on the deciding machine.
- `NpcWorldSim`, `SettlementPopulation` and `SettlementAlarm`'s rally are **server-or-offline** (`!Network.IsNetworked || Network.Server`), not `Network.Simulates(this)`. `NpcSpawn.Create` makes the same check itself.
- An `InventoryItem` an NPC carries needs its `itemPrefab` registered as a network prefab; projectiles and equipped visuals must **not** be. See [spacegame-multiplayer](.claude/skills/spacegame-multiplayer/SKILL.md).
- War: `WarPartyDirector` is server-only (`Network.Decides`), like `NpcWorldSim` beside it. `GroupMembership` is stamped in `NpcSpawn.Create`'s `beforeSpawn`, before `NetworkObject.Spawn`, so a member's `NpcRandomLoadout` roll is already seeded on spawn. A war cry replicates as `AgentAction.WarCry` with a line index, not the text, so every machine reads its own copy of the tribe's `hostileLines`. `FactionGoodwillNetwork.Notify` posts host-local rather than through `Send`'s skip-the-host rule — a notice is an event with nothing to hold, so skipping the host would mean the host never hears its own war party is coming. `EntityFaction` is not replicated, so `RosterValidation` requires every non-Rider member's prefab to already serialize the tribe's faction.

## Persistence

`AgentController` implements `IPersistentEntity`, so **every agent is save-eligible with no opt-in**. Savers live outside this tree in [Core/Persistence/Adapters/](Assets/Game/Scripts/Core/Persistence/Adapters/AgentStateSaveable.cs): `AgentStateSaveable` (key `"agent"` — target/lastAttacker as `SaveRef`, last-known position, `timeSinceSeen`, `profileId`, patrol index/direction), plus `PatrolSaveable`, `SearchSaveable`, `AlertResponseSaveable`, `NoiseInvestigationSaveable`; and the generic `TransformSaveable` + `HealthSaveable`. Add them inside the prefab's builder, then run `Tools/Save System/Wire Saveable Prefabs`. Details: [Persistence.md](Persistence.md).

## Gotchas

- **There is no legacy brain, and a dozen modules named in older comments no longer exist.** Deleted 2026-09-22 for having zero live instances: `NpcBrain`/`EnemyBrain`/`IAgentBrain`/`WanderBehaviour` (the four scene NPCs on them were re-authored onto `WanderModule`+`IdleLookAroundModule`+`InteractionFocusModule`, which is all they observably did — carrying no `EntityFaction`, their player reaction could never resolve a target), `CoverModule`/`CoverPoint`, `AirWanderModule`, `FlockingModule` (use `HerdModule`), `ApproachModule`, `HuntModule`, `FacePlayerModule`, `TurretModule` (the live turret is `RocketLauncherTurret`), `WeaponMount`/`WeaponSelector`, `DuneRiderController`, `StrideStopProbe`, and the four `EntityProfile_*` authoring components with their editor. Their savers went too; `PursuitSaveable` now covers `KeepDistanceModule` alone, and `PatrolSelectionMode` moved to [PatrolModule.cs](Assets/Game/Scripts/agents/Modules/Patrol/PatrolModule.cs). An agent with no movement module idles and logs a warning. Build creatures from a builder in [Assets/Game/Editor/Creatures/](Assets/Game/Editor/Creatures).
- **Until 2026-09-07 nothing ever called `AlertBroadcaster.Broadcast`, so "alert allies" had never happened**, and the receivers only sat on the five robot prefabs. It is wired through `AgentTargeting.TargetAcquired` and `ProvocationModule.Provoke` now, but only for a target the agent found itself or was hit by: a target that *arrived by alert* is forced with `seen == false` and is never passed on, which is the whole cascade cap. Put both components on every member of a faction that should share a fight (the nomad builders do not yet), and never call `Provoke` with `announce: true` from anything that received the target second-hand. `NoiseReceiverModule`'s aggro branch skips allies for the same reason: a `Hurt` noise carries the attacker, and a Clanker hearing a nomad scream must not turn on the Clanker that shot it.
- **Agents stand on the NavMesh, and the NavMesh is not the ground.** The world bake floats a median of 0.257 m above the terrain (max 0.600) — see [NavMeshSystem.md](NavMeshSystem.md). `AgentGroundConform` corrects it per frame. A constant `baseOffset` cannot: the error is terrain-dependent, so a single number leaves the body buried at one end of the range and floating at the other. Every agent prefab's `baseOffset` is 0 and should stay that way.
- **`baseOffset` has three authors now** — the prefab's own value, the ground correction and the mounted-jump arc — summed in `NavMeshAgentMotor.ApplyBaseOffset`. Assign `agent.baseOffset` directly from anywhere else and whichever writer runs later in the frame silently erases the rest.
- **Nine of the ten agents are bipeds, so the slope lean defaults low** — `slopeFollow` 0.35 (`AgentGroundConformWiring.BipedSlopeFollow`); a biped spends the slope in its legs and leaning it like a many-legged body reads as falling over. The Golem is a biped (`Bone_Thigh/Shin/Foot_L/R`, nothing else), and so is the DuneRat despite quadruped bone names — 0.29 m forelimbs clear of the ground against a 0.99 m hind chain. Only the Vrescal hexapod gets `ManyLeggedSlopeFollow` (0.8). Applied **only when the component is added**, so tuning survives.
- **The node the slope lean is written to is animated on the Golem and the DuneRat and on nothing else.** `AgentGrounding.Baseline` works out which case it is by reading the transform back rather than from a per-prefab flag. Replace it with a flag and you get one of two silent failures: the lean erases the root-bone animation, or it multiplies into itself every frame and the body spins.
- **`AgentAnimatorDriver.animator` is empty on every nomad prefab by design — the driver finds it, so it must be asked, not assumed.** The Animator sits on the model child and the driver looks it up in `Awake`, but components on one object awake in no guaranteed order and `AggressionTelegraphModule.OnEnable` calls `SetIsAiming` immediately. Reading the field directly there hits the prefab's empty reference and throws `UnassignedReferenceException` on every nomad spawn. `SetIsAiming` therefore goes through `ResolveAnimator()`, the same lookup `Awake` uses. Do not write `animator?.Foo()` on any `UnityEngine.Object`: `?.` skips Unity's overloaded null check, so an unassigned field throws instead of being skipped.
- **No `EntityFaction` → invisible to every targeting module, silently.** Needs both a `FactionDefinition` and `GlobalRelationships.asset`. `EntityFaction.Ensure(go, faction, table)` on spawn paths.
- **Peaceful = no Hostile row, a `Neutral` `defaultStance`, AND a `Neutral` row toward every faction whose own default is `Hostile`** (today only `ClankerFaction`) + `ProvocationModule` (`leashRange` ≤ `AgentTargeting.loseRange`). Hostile is unilateral, so without that last row the Clankers' default makes the pair Hostile from BOTH sides and the "peaceful" creature attacks every robot it sees — the drifters did exactly that. Adding a Hostile row "for completeness" makes the whole faction attack on sight; so does a `Hostile` default, which is checked on every pair with no row. `FaunaFaction` has a Neutral default and its only rows are the two Clanker `Neutral` ones; `WildlifeFaction` is already Hostile to the player. **Only `ClankerFaction` sets `defaultStance = Hostile`** — that one checkbox is what makes them hostile to every people-faction, including ones added later that nobody remembers to write a row for, and their two `Neutral` rows toward Fauna and Wildlife are what keeps them off the animals (a row beats the default).
- **Three ways a "neutral until provoked" NPC half-works with a clean console**, all three found on the drifters at once. (1) No attack module: `ProvocationModule` + `ChaseModule` alone give a provoked NPC that walks up to you and stands there for ever — nothing ever swings. (2) No `ChatterModule`: `AggressionTelegraphModule` barks only through it, so the NPC turns to face you, plants its feet and says nothing. (3) An unarmed body with `aimWhileDrawn` on: `IsAiming` sends `AstronautArmature.controller` to the full-body `HumanM@AssaultRifle_Aim01`, so it levels an empty pair of hands. `SculptCharacterBuilder` now adds `CloseCombatModule` and `ChatterModule` and turns `aimWhileDrawn` off.
- **A creature turning on the spot reports no velocity, so nothing tells the animator it is turning.** A NavMeshAgent picking a new heading rotates the transform without translating it: `SpeedX`/`SpeedY` stay at 0, the blend tree sits on Idle, and the animal swings round with its feet planted like a turret. [`AgentAnimatorDriver`](Assets/Game/Scripts/agents/Animation/AgentAnimatorDriver.cs) now also measures **yaw** off the transform — same reasoning as the velocity, so it works on a watching machine where only the NetworkTransform is moving the body — and publishes it as `TurnSpeed`, a signed rate in **degrees per second, positive turning right**. It is *optional*: the driver looks the parameter up once per controller and skips it where there is none, because writing a parameter a controller does not have logs a warning every frame per agent. Appa and the robot horse have turn clips so far. To add them to another creature: two looping in-place clips, a `TurnSpeed` float, and a blend tree with the left clip on the **negative** side. **A turn clip and `NavMeshAgent.angularSpeed` are one number, authored in two files.** The clip steps the feet through a fixed arc per cycle; the agent turns the body at whatever rate it likes, and the difference is skating. Appa's clips cover ~33° per 0.75 s cycle, so `AppaBuilder.TurnSpeed` is 45 °/s and sets both the agent's `angularSpeed` and the blend-tree thresholds. It was 130 before there was a clip to disagree with — three times faster than the feet are placed. The same derivation gives a *fast* mount its speed without skating: `RobotHorseBuilder` reads the stride the anim script prints (1.13 / 5.53 m/s at scale 1), multiplies by the scale and the `animatorSpeedScale`, and sets the agent speed and the blend thresholds to that product — 13.9 m/s at the gallop.
- **A collider parented to a BONE is 100x too big.** Every transform in an imported FBX carries `lossyScale = 100` (the centimetre convention — see [ArtPipeline.md](ArtPipeline.md)), and a bone is no exception. `AppaBuilder.AttachPetTarget` asked for a 0.75 m sphere 0.35 m along the muzzle and got a **75 m sphere centred 38 m away**; the player stood inside it, and a raycast that begins inside a collider does not report hitting it, so the pet prompt could never appear. Divide by `bone.lossyScale` (the builder sets `localScale = Vector3.one / boneScale` and then asserts the world radius came out right), and put the volume ON the bone rather than offset along it — a bone's local axes are whatever the export left them as.
- **`AgentTargeting.ForceTarget` has no self-check.** Anything that hands a creature its own transform gives it a target it can never lose and can never miss: it chases itself at distance 0 and melees itself forever, and to a player that is an animal losing health with no attacker anywhere. `ProvocationModule` guards this (`resolved == transform` → ignore); `NoiseReceiverModule` did not, and now does. Guard at every call site, or in `ForceTarget` if a third one appears.
- **`HealthReactionModule.logDamage`** prints amount, source path and remaining health for anything that seems to be taking damage from nowhere. `HealthComponent.LastDamageSource` was always recorded and nothing read it back out.
- **Never set a player animator trigger directly — go through [`PlayerAimRig.PlayGesture`](Assets/Game/Scripts/Characters/Player/Combat/PlayerAimRig.cs).** That component owns the masked Upper Body layer outright and rewrites its weight every frame from whether an item is held, so a trigger set from outside plays its clip on a layer weighted **0** and nothing appears. Petting is done with a free hand, which is exactly the case where the weight is 0. Two things are needed and `PlayGesture` does both: hold the layer up for the clip's length, and raise the `Gesturing` bool — the layer's hold poses are entered from Any State on `HoldStyle Equals n`, which is *continuously* true, so with empty hands `→ Empty` fires every frame and evicts the gesture after about one frame. `PlayerPetGestureBuilder` and `PlayerGestureBuilder` each stamp `Gesturing == false` onto every other Any State transition on the layer.
- **A trigger collider only offers its interaction when the `IInteractable` is on that same GameObject.** [`Interactor.ResolveAlongRay`](Assets/Game/Scripts/Gameplay/Interaction/Core/Interactor.cs) treats a trigger as a detection volume rather than a surface: it never inherits an interactable from a parent, and the ray passes straight through otherwise. That is not a limitation to work around — it is the mechanism for a body-part interaction. [`PettableModule`](Assets/Game/Scripts/agents/Modules/Social/PettableModule.cs) sits on a trigger parented to Appa's `head` bone, so "look at his head and press E" costs no raycast filtering and no distance test. Put the same component on the agent root instead and the body's solid collider answers for it, which offers "pet me" from every square metre of a 5.75 m animal including his tail and the underside of his feet. Parent it to the **bone**, not to the root, or the volume stays behind when he puts his head down to graze.
- **A sight line aimed at a target's ORIGIN is aimed at the ground, and the ground wins.** Every character's origin is at its feet, so `PerceptionModule` used to raycast from the eye to a point ON the terrain: the ray grazed every rise between the two and ended inside the ground itself, and the Clankers — 80 m of authored sight — acquired the player only inside `proximityAcquireRange` (4 m). `AimPointOf` now aims at the target's root-collider centre (or `targetAimHeight` above the origin), for sight and for muzzle checks alike; `PerceptionAimTests` stands a player behind a knee-high rise. **The project queries triggers by default (`queriesHitTriggers: 1`), so every NPC visibility ray must pass `QueryTriggerInteraction.Ignore`** — a ship's `BreathableAir` trigger hid a player 370 m away from 12 of 15 NPCs, and until 2026-09-17 nomads ran on unchosen 110°/35 m/5 s defaults; `PerceptionLineOfSightTests` covers both triggers and low cover. **`Network.Simulates` is the wrong gate for a scene rule.** It answers true on a client for anything without a spawned `NetworkObject` — a settlement root included — so `SettlementPopulation` called `World.Spawn` on a client 29 times in one session and was refused every time. Scene-level deciders use `Network.Decides` (server or offline); `Simulates` is for entities.
- **A creature's hearing range and its flee trigger are two different numbers, and the gap between them is a creature that ignores you.** A gunshot carries `Weapon.gunshotNoiseRadius` = **40 m**; `FleeModule.triggerRadius` on Appa is **22 m**. Shot from anywhere in between, he heard it, acquired the shooter through `NoiseReceiverModule`, went to `Mood.Fleeing` — and then kept walking his errand, because `FleeModule`'s own proximity hysteresis never flipped. Measured: shot from 30 m, and several seconds later he was **7 m closer to the gun**, at 0.62 m/s. He read as completely unbothered by being shot at. `triggerRadius` answers "did something frightening get *close*", which is the right question for a creature noticing a predator by itself and the wrong one for an alarm that arrived from further away. So [`FleeModule.Alarm()`](Assets/Game/Scripts/agents/Modules/Movement/FleeModule.cs) sets the flag directly and `FightOrFlightModule` calls it on entering `Fleeing`: whoever decides the creature is frightened says so, and `FleeModule` decides where to run. Stopping is still `safeRadius`'s job, so an alarm cannot pin it running forever.
- **A dwell that lasts tens of seconds needs a bool, not a trigger.** `NpcTask.dwellFlag` names an animator bool that [`NpcTaskModule`](Assets/Game/Scripts/agents/Tasks/NpcTaskModule.cs) holds true for as long as the NPC works a site and clears the moment it moves on — `IsGrazing` on Appa's feeding task, which dwells 120–300 s. A trigger would fire once and leave the animal standing at attention for the rest of its meal. `SetDwellFlag` clears the previous flag before setting the new one; without that an animal that goes from grazing to drinking does both at once.
- **Out-ranking a module is not the same as switching it off, and for flee-vs-chase the difference is a creature that walks at the thing it is fleeing.** `FleeModule` (Override, 30) beats `ChaseModule` (20) *only on the frames it returns an intent*. It returns `null` whenever it cannot find a NavMesh point to run to — and `null` means **pass**, so the frame falls straight through to chase. Measured on Appa: nominally FLEEING, he covered 11.5 m toward the shooter, closed to 3.8 m and then legitimately tripped his own "cornered" rule. Two halves to the fix, both landed: `FightOrFlightModule` now enables flee and the combat modules as **mutually exclusive** sets rather than stacking them by priority, and `FleeModule.TryGetFleeDestination` fans out (seven directions × four distances) instead of sampling one point at full `safeRadius` and giving up. Any module pair where the loser would move the agent the *opposite* way needs the same treatment.
- **`FleeModule` on a peaceful creature finds nothing to run from.** Its default path resolves a threat by *faction relationship*, and a Fauna creature has no rows in `GlobalRelationships.asset` — so it is Neutral toward everything, the scan returns null, and the animal stands there being shot with a completely clean console. Set `fleeFromCurrentTarget`, which reads `AgentTargeting.Target` instead; `ProvocationModule` (damage) and `NoiseReceiverModule` (gunfire) are what put a target there. Do **not** "fix" it by adding a Hostile row toward the player — that makes every creature of that faction attack on sight.
- **Gunfire reaches AI through `Noise`, not through the damage path.** A shot that misses damages nothing, so `HealthComponent` never fires and nothing else would notice it. `Weapon.TryFire` calls `ReportGunshot` after a round actually leaves (not when a charge starts), and the agent-side guns emit from `AgentRangedCombatModule.FireOne` and `RocketLauncherTurret.Fire`. All of them are on the **deciding** machine only — `Weapon` by construction (`TryFire` is reached from `Use()` alone; `Present()` calls `Fire` directly), the others behind `authority.SimulatedHere`. Emitting on a peer would be heard by a copy of the creature that cannot act on it, while the copy that can heard nothing. `gunshotNoiseRadius = 0` makes a weapon silent to AI without silencing its sound.
- **A gunshot target does not stick on its own.** `NoiseReceiverModule`'s aggro branch is a bare `ForceTarget`, and `AgentTargeting`'s staleness pass drops it within seconds — for a Fauna creature nothing can ever re-acquire it, so the animal takes two steps and forgets. `FightOrFlightModule` re-feeds it through `ProvocationModule.Provoke` so the leash holds it. Anything else that force-targets a peaceful creature needs to do the same.
- **A script-added module keeps priority 0** — Unity does not call `Reset()` for `AddComponent`, so it ties with wander; set `priority` explicitly. And **two `AgentTargeting` components** — `[RequireComponent]` may already have added one; guard builders with a `GetComponent` null check. **A module returning `MoveIntent.Idle()` while merely waiting starves everything below it** — return `null`.
- **`*Builder` scripts in `Assets/Game/Editor/` overwrite prefabs wholesale** with no warning; hand-added components vanish on rebuild. `GolemBuilder` lost the Golem's `SaveableEntity` this way.
- **Feet skate** when only `animationSpeedMultiplier` / `walkAnimBoost` were tuned — those pick the *clip*. `animatorSpeedScale = groundSpeed / strideSpeed` sets the *rate*, applied once in `Awake`, and is global (attacks slow with it).
- **The `"Meele"` swing is sped up in the controller, not in code.** On `AstronautArmature.controller` it is `HumanM@ThrowSpear01_R`, a full-body 2.4 s spear throw whose first ~0.9 s is standing prep; played raw, a provoked drifter stood still, wound up for two seconds and released at ~2.0 s, long after the player had moved. The state now plays at `m_Speed` 2 and both transitions into it start at offset 0.35 (0.84 s in, just before the wind-up at ~0.93 s on the Spine Twist / Right Forearm Stretch curves): release ~0.55 s after the trigger, whole swing ~0.78 s. The state is shared by `Nomad.prefab` and every drifter, so tune it there, not per prefab. Two things it did not change: damage still lands on the trigger frame (`CloseCombatModule.Attack`), ~0.55 s ahead of the release, and `attackCommitDuration` (0.32 s) is shorter than the swing, so a target that leaves mid-swing is chased with the throw still playing on the legs.
- **Trigger names disagree by default:** driver fires `"Die"`, `HealthReactionModule.dieAnimTrigger` = `"Death"`, `CloseCombatModule` = `"Meele"`, `AgentRangedCombatModule` = `"AssualtShoot"` — the misspellings are real. `Golem.controller` carries both `Die` and `Death`.
- **`PerceptionModule.occlusionLayers` left at `Nothing`** falls back with a warning and the agent shoots through walls intermittently. A **`LeggedLocomotion` left in `NetAuthority.simulationDrivers`** makes remote copies slide with still feet.
- **A module that throws is switched off, not the creature.** Every module tick and every `TryGetFacing` runs through `AgentController.RunModule` inside `Fault.Run`; a throw is read as `null` — "I pass" — so the frame falls through to the next module instead of starving every module below the broken one. After 5 faults in 10 s that component's `enabled` goes false, so `IsActive` goes false and the controller stops ticking it for good; the creature keeps its other behaviours. `RunModule` returns `null` for a module that is not a `Component`, which every real module is. See [Diagnostics](Diagnostics.md).
- **Provoked NPC walks instead of running:** `NavMeshAgent.speed` must be the **run**; scale `walkSpeedMultiplier` down from it, because `ChaseModule` asks for `isRunning`.
- **Loot duplicates on load** — a death reaction ran during a restore; check `HealthComponent.IsRestoring`. **A spawner-owned group duplicates on load** unless members call `SaveableEntity.DisownToExternal()`; this is why `NpcSpawn` deliberately avoids `GameServices.World.Spawn`. **It also duplicated on an in-session reload (quickload) until 2026-09-17**, for a different reason: `NpcSpawn.Create` called `NetworkObject.Spawn()`, whose default is `destroyWithScene: false`, and NGO's `LoadScene(Single)` carries every such root through DontDestroyOnLoad into the new world — 21 of 113 group members, riders and hulls survived one quickload beside their rebuilt copies. It spawns with `destroyWithScene: true` now. That also means a member in a chunk scene that unloads is despawned with it rather than rescued; a live member is always within `despawnRadius` (360 m) of a player and so inside that player's loaded 3×3 of 500 m chunks, and a fold happens a sim tick later, well inside the 10 s `unloadGracePeriod`. **The outgoing world's sim must stop on the reload itself.** With members despawned at `LoadScene` but the old scene alive for the ~20 frames the new one takes, `NpcWorldSim` read every group as wiped out, `WarPartyDirector` resolved the Sky party as Defeated and posted "their resolve is weakening" over the loading screen, and the sim spawned fresh members into the dying world (seen 2026-09-17). `NpcWorldSim` listens through a `SceneEventHook` and stops ticking on `SceneEventType.Load` + `LoadSceneMode.Single`; the new world's sim rebuilds everything from the save. **A settlement outside the chunk scenes doubles its population on every reload unless it waits for the ground.** `SettlementPopulation` spawns through `GameServices.World.Spawn`, and the streamer migrates each person into the chunk scene under them, so they are saved under `chunk:x,y` and restored only when that chunk loads. A Clanker town lives in that same chunk, so it loads with its people. The Sky City lives in `persistentScene`: on a reload it counted 0, spawned, the new people pinned the chunks loaded, and the saved 16 hydrated beside them — measured 24 two waves in. `keepGroundChunksLoaded` holds the clock until those chunks are `Loaded` (and keeps them so); measured after the fix: 16 before save, 16 after reload, all 16 carrying the instance ids from the save file.
- **Every NPC aims at the host's head** unless `EntityEquipmentController` sets `Weapon.ExternallyAimed` (keep `aimHeldItem` on) — the server owns every NPC and `Weapon` aims at `Camera.main` for its owner.
- Bone-parented rigs freeze mid-stride off screen: `animator.cullingMode = AlwaysAnimate`. A humanoid FBX re-export can silently downgrade to `isHuman = false` — the character then stands still with a clean console.
- **Rosters and war parties, six traps.** `NpcSpawn.Create`'s `beforeSpawn` is the only place a value read in `OnNetworkSpawn` can still be set — `GroupMembership` is stamped there. A war party's mount stays Fauna; only the rider it seats takes the tribe (`GroupMembership.Enlist`, `IsFighter` false for anything carrying `NpcPassenger`). `RestoreRow` raises no event, so a war reopened by a load is not seen by `OnBandChanged`; `WarPartyDirector.Reconcile` walks the ledger each tick after adopting restored parties instead, must not end a war whose quarry has not bound yet, and starts a war it reconciles (rather than one it adopts alongside a restored party) at full `partyCooldown` — spec §7: the cooldown itself is never saved. `NpcWorldSim.RestoreRecords` removes every runtime group before matching records, so a restored party's session-local flags (`WipedOut`, `DisbandWhenFolded`) never carry over from the session being replaced; `NpcGroup.Record.wipedOut` is saved for the same reason — a party wiped out just before a save resolves as Defeated on load rather than respawning at full strength — and a duplicate restored party is released (`ReleaseGroup`), never popped out of view. Never hand-edit a nomad's `NpcRandomLoadout.candidates`: baked from `FactionRoster.handItems` by `NomadPrefabBuilder`, `RosterAssetTests` fails otherwise, and a partial rebuild is worse than none — re-run the whole builder (`Build Sand Nomad NPCs`, `Build Sky Nomad NPCs` for the four Sky nomads, `Build Sky Soldier NPC` for the soldier), which also re-chains `Sync Network Prefabs` → `Wire Saveable Prefabs` → `RagdollWiring`; an interrupted run has left prefabs without savers, `RagdollRig` or `AgentGoal`. A runtime group's template must stay in the sim's `templates` list (`runtimeOnly`), or a saved war party's record cannot find its template on load and is silently skipped. A rider who dismounts (`NpcPassenger.Dismount` clears `ownsRider`) is in no mount's saddle and not in `NpcGroup.Live`; only `NpcGroup.Fighters` still holds them, so every fold, disband and restore teardown goes through `NpcWorldSim.DespawnMembers`, which despawns un-seated fighters itself and leaves seated ones to their mount's `NpcPassenger.OnDestroy` — skip it and riders pile up in the desert while each re-spawn seats fresh ones. `NpcGroup.ApplyRecord` ignores a `rosterSeed` of 0 (an older save), keeping the id's `StableHash`. **Flying parties: the vessel goes before its riders, and nothing waits for `Finished`.** Despawning riders first leaves seated NetworkObjects under a hull that the next despawn lifts to the scene root; `NpcWorldSim.DespawnTransport` runs before `DespawnMembers` on every fold, disband and restore teardown so the pilot's despawn hook sets them down. `VesselPilot.Finished` is never raised for a hull despawned mid-run (a fold), so `Delivered` is polled from the pilot's seat count and wreck flag, not event-driven; `Done` alone never means delivered. `NpcGroup.Transport` is runtime only: a group record holding a live vessel must not be removed (`DisbandWhenFolded` waits on it) or the hull flies on with nobody to despawn it. Dock reuse, retry-on-failed-landing and the in-flight abandon exemption: [SkyTribe.md](SkyTribe.md) Gotchas.

## Extending

**New creature** (copy GolemBuilder.cs, menu `Tools/Creatures/Build Golem Prefab`):
1. Mesh + rig authored in the model library (see [ArtPipeline.md](ArtPipeline.md)); verify `avatar.isHuman` for humanoids.
2. Prefab under `Assets/Game/Prefabs/agents/…`. Reuse the FBX's own `Animator`, `applyRootMotion = false`, `cullingMode = AlwaysAnimate`.
3. Collider + kinematic `Rigidbody` (`useGravity = false` for NavMesh creatures).
4. Motor: `NavMeshAgent` + `NavMeshAgentMotor` (speed = run, `walkSpeedMultiplier` = walk/run), or `LeggedDriver`, or `FlyingRigidbodyMotor`, or `RigidbodyMotor`.
5. `AgentController` on the root; assign `MotorComponent` + `animatorDriver`.
6. `EntityFaction` (faction + `GlobalRelationships.asset`), then `HealthComponent` + `HealthReactionModule` (+ `EntityLootTable`).
7. Modules: one Fallback (`WanderModule`/`PatrolModule`) plus reactive/combat ones, each with an explicit `priority`. Perception: `PerceptionModule` (set `occlusionLayers`), `AlertBroadcaster`/`AlertReceiverModule`, `NoiseEmitter`/`NoiseReceiverModule`.
8. Animator controller in `Assets/Game/Art/Animations/Creatures/` with the exact parameter names above; set `animatorSpeedScale`.
9. `SceneTracked` (`policy = Migrate`) for roamers; saveables + `Tools/Save System/Wire Saveable Prefabs`; `NetworkObject` + `NetworkedHealthComponent` + `NetAuthority` + `Tools/SpaceGame/Multiplayer/Sync Network Prefabs`.
10. Into the world via `NpcWorldSim.templates` (inlined in `Assets/Game/Scenes/world/persistentScene.unity`), `SettlementConfig.asset → robotPrefabs`, or a hand-placed chunk instance.

**New behaviour module** — last resort; first check whether existing data (`TargetingProfile`, `NpcTask[]`, a relationship row, a different priority) answers it:
1. Decides *where*, not *how*? Set `ClaimsMovement => false` and write `AgentGoal`; `GoalTravelModule` walks there (`NpcTaskModule` is the worked example).
2. Decides only where the body *points*? Implement `IFacingModule` — not a movement module returning `StopAndFace`.
3. Otherwise subclass `BehaviourModuleBase` in the matching `Modules/` folder; `Reset() => SetPriorityDefault(...)`; override `ModuleDescription`.
4. In `Tick`: read the target from `context.Targeting` (never query the registry for a hostile; use `TargetResolution.Refresh` for non-hostiles); return `null` to pass; run expensive queries on an interval; keep collections instance-level, not static.
5. Reset per-module state in `OnEnable` (respawn, streaming and loads re-enable agents). No authority checks inside the module.
6. Attack-style modules need enter/exit hysteresis (`rangeExitFactor`) or the winner flips every frame at the range boundary and the agent stutters.
