# Artifact Icons and Missing Models — Design

Date: 2026-08-16

## Problem

Several `InventoryItem` assets under `Assets/Game/Resources/Items/` point their `icon`
field at a sprite belonging to a *different* item. The icons that are not outright wrong
were each generated by hand through `IconGenerator`, an `EditorWindow` with manual
pitch/yaw/zoom sliders, so no two share a framing convention. Three artifacts have no
model at all — their prefab visual is a raw Unity primitive.

### Confirmed wrong icon assignments

Verified by resolving the `icon` GUID in each `.asset` back to a sprite path.

| Asset | Its `itemPrefab` (and model) | `icon` currently resolves to |
|---|---|---|
| `basicgun` | `Guns/Gun.prefab` → `cixinGunFinal.fbx` | `Items/GrapplingHook.png` (the retro blaster) |
| `BallLightningWeapon` | `Guns/CixinGunEquipped.prefab` → `cixinGunFinal.fbx` | `Items/LightningSpell.png` (a grey sphere) |
| `Leash` | `Gadgets/Leash.prefab` (a Cylinder) | `Items/Lasso.png` (the lasso) |

`Assets/Game/Art/Sprites/Items/BallLightningWeapon.png` already exists and is a correct
render of the Cixin rifle, but no asset references it.

### Artifacts whose prefab is a bare Unity primitive

| Asset | Prefab visual |
|---|---|
| `AntiGravityPotion` | builtin Capsule |
| `LightningSpell` | builtin Sphere |
| `Leash` | builtin Cylinder |

## Goals

1. Every `InventoryItem.icon` is a render of that item's own `itemPrefab`.
2. One consistent framing, lighting and background across the whole icon set.
3. Solid neutral grey background (`#3A3A3A`).
4. The three primitive-only artifacts get real Blender models.
5. A report listing every artifact still missing a model.

## Non-goals

- Rewriting `IconGenerator.cs`. It stays as the manual/one-off tool; the batch tool is
  added beside it.
- Changing any gameplay script, collider, or network wiring.
- Re-authoring `cixinGunFinal.fbx` so the ball lightning weapon has its own model. That
  is reported, not fixed.

## Design

### 1. Three new Blender models

Built with the existing library conventions: a generator `.py` plus a `.blend` under
`Assets/Game/Art/Models/_Source~/components/props/`, the same place `expedition_backpack`
and `field_backpack` live. Materials are linked from `palette.blend`. Export goes through
`_exportlib.export()` to `Assets/Game/Art/Models/Items/`.

The `.blend` is the source of truth and is committed. `_buildlib.start()` refuses to
overwrite an existing `.blend`, so re-running a generator is safe.

| Model | Replaces | Concept | Key palette materials |
|---|---|---|---|
| `weather_station_device` | LightningSpell's Sphere | Handheld storm-caller: tripod-braced short mast, anemometer cups, barometer dial face, vent grille, whip antenna with lit tip | `Mat_Paint_Blue_Station`, `Mat_Metal_Steel_Worn`, `Mat_Emissive_Green_CRT`, `Mat_Emissive_Amber` |
| `antigrav_device` | AntiGravityPotion's Capsule | Grav emitter: split torus ring with a core suspended in the gap, servo-jointed yoke, coil windings | `Mat_Metal_Chrome_Scuffed`, `Mat_Metal_Copper_Oxide`, `Mat_Neutral_Slate_Dark`, `Mat_Emissive_Green_CRT` |
| `leash_device` | Leash's Cylinder | Tether emitter: cable spool with a ratchet housing, clip hook, grip handle, charge indicator | `Mat_Metal_Steel_Dark`, `Mat_Paint_Safety_Orange`, `Mat_Plastic_Rubber_Black`, `Mat_Emissive_Amber` |

Scale: each is a carried item, sized to roughly 0.25–0.4 m on its longest axis so it sits
correctly in the hand and drops at a believable size.

### 2. `BatchIconGenerator.cs`

New editor script at `Assets/Game/Editor/AssetPipeline/BatchIconGenerator.cs`, menu item
`Tools/Generate All Item Icons`.

Per `InventoryItem` found under `Assets/Game/Resources/Items/`:

1. Instantiate **`item.itemPrefab`** — the exact object the asset references. Never a
   same-named sibling prefab. If `itemPrefab` is null the item is skipped and reported.
2. Move the instance to an isolated preview scene on a dedicated layer so no world
   geometry, skybox or scene light can leak into the shot.
3. Strip `LineRenderer`, `TrailRenderer` and `ParticleSystem` components before framing.
4. Compute combined `Renderer.bounds` over the remaining enabled renderers.
5. Frame with a fixed 3/4 view, orthographic size derived from the bounds so every item
   fills the same fraction of the frame regardless of world scale.
6. Render with `clearFlags = SolidColor`, `backgroundColor = #3A3A3A`, opaque alpha, three
   neutral directional lights (key / fill / rim), post-processing off.
7. Write `Assets/Game/Art/Sprites/Items/<assetName>.png`, import as Sprite, assign to
   `item.icon`, mark dirty, save.

#### Why steps 3 and 5 exist

`Lasso.png` is currently a near-invisible hairline and `GrapplingHook.png` is off-centre.
Both are caused by the same thing: those prefabs carry a `LineRenderer` whose bounds are
far larger than the mesh, so any bounds-fit framing zooms out until the actual item is a
few pixels. The current tool has no bounds fit at all — it uses a hand-set zoom slider,
which is why each existing icon has its own framing.

#### Per-item angle override

A small serialized table maps an asset name to a pitch/yaw override. Used for exactly one
case at present: `basicgun` and `BallLightningWeapon` share `cixinGunFinal.fbx`, so they
are shot from deliberately different angles to stay tellable apart in the hotbar.

### 3. Prefab rewiring

`AntiGravityPotion.prefab` and `LightningSpell.prefab` and `Leash.prefab` have their
primitive `MeshFilter`/`MeshRenderer` replaced by the new FBX. Everything else on the
prefab is kept: `PickupableItem`, `NetRelay`, `DropItemPhysics`, `SaveableEntity`,
`TransformSaveable`, and each prefab's own gameplay script. Prefab GUIDs are unchanged, so
every existing reference — including the network prefab list — keeps resolving.

Colliders are resized to the new mesh bounds. Primitive colliders are kept as primitives
(box/capsule) rather than swapped to mesh colliders, since these are pickups that get
thrown around by `DropItemPhysics` and a convex mesh collider would be wasteful.

### 4. Display name fixes

`RocketTurret.asset` and `Leash.asset` both carry the `InventoryItem` default
`itemName: "NewItem"`, which is what the UI shows. Set to `"Rocket Turret"` and `"Leash"`,
matching the spacing style of `"Ruin Scanner"` and `"Wing Pack"`.

### 5. Missing-model report

Delivered as a table in the final response, one row per artifact, with a category:

- **primitive** — visual is a raw Unity builtin mesh (resolved by this work for the three above)
- **borrowed** — reuses another item's model, so it has no identity of its own
- **third-party** — visual comes from a purchased/free asset pack rather than the project's own library
- **own model** — has an authored model in `Assets/Game/Art/Models/`

## Verification

- Read back each regenerated PNG and confirm visually that it depicts the item its asset names.
- Re-run the GUID resolution script and confirm no two artifacts share an icon GUID, except
  where they legitimately share a model.
- Confirm Unity compiles clean and the console has no import errors.
- Confirm the three rewired prefabs still carry their original component set.

## Risks

- **The `.blend` files may carry hand edits.** `_buildlib.start()` refuses to overwrite an
  existing `.blend` for this reason. These three are new files, so there is nothing to
  clobber, but the generators must not be re-pointed at existing library `.blend`s.
- **Icon regeneration touches every item asset.** The diff will be larger than three files.
  This is intended — the user asked for the whole set to be made consistent.
- **`Leash.prefab` has a thinner component set** than the other gadgets (only
  `LeashArtifact.cs`, no `PickupableItem`/`NetRelay`). Rewiring it must not silently add or
  drop components; whatever it has today it keeps.
